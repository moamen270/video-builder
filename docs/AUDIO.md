# Audio — voice, timing, effects, laughs

All audio is produced locally. The TypeScript engine (`engine/src/audio.ts`)
orchestrates; the Python package `py/vb_audio` (managed by `uv`) does the
model work; ffmpeg does effects and mastering.

Run Python via `uv run --project py vb-audio <cmd>`. `vb_audio` never prints
data to stdout — spaCy and torch write there — so every command takes an
`--out` file.

## 1. Speech: Kokoro-82M with forced word timestamps

`py/vb_audio/tts.py` wraps `KPipeline` (one pipeline per language code,
`a` American / `b` British, chosen from the voice prefix). For each scene:

1. synthesize `speech` at the scene's `voice` and `speed`;
2. take Kokoro's **per-token `start_ts`/`end_ts`** — Kokoro predicts a duration
   for every phoneme and misaki maps phonemes back to the source tokens, so
   every word gets an exact interval *by construction*. We never run Whisper
   or any re-alignment: that would introduce transcription errors on the very
   text we already know;
3. punctuation tokens have no timestamps → snap to neighbours, then glue onto
   the previous word so a caption shows `fast!` not `fast` + `!`;
4. append `pauseAfter` seconds of silence; write 24 kHz PCM16 wav.

Output: `build/alignment.json` — `{ scenes: [{ sceneId, file, duration, tokens:[{text,start,end}] }] }`.
That file is the only bridge between audio and timing; the resolver turns
`start` into frames.

### Cache

`ensureAudio` hashes each scene's text, voice, speed, voiceFx, pauseAfter (and
clip file size/mtime) — `v4` key — and reuses `build/audio/<id>.wav` when
unchanged. Editing one line re-synthesizes one scene (~2 s); a cold model load
is ~13 s.

### Voices

Kokoro voices used: `af_heart af_bella af_nicole af_sarah af_sky am_adam
am_michael am_fenrir am_puck bf_emma bf_isabella bm_george bm_lewis`.
Measured median F0 of the raw voices (Hz): `bm_lewis 94 · am_michael 119 ·
am_puck 121 · am_adam 122 · am_fenrir 139 · bm_george 153`. Names are not a
guide to depth — `am_fenrir` sounds young despite the name. Measure, don't guess.

Per-scene overrides: `voice`, `speed`, `voiceFx` — this is how a second
character (Robin) speaks in a video narrated by Batman.

## 2. Voice FX (ffmpeg chains)

Applied after synthesis with `applyVoiceFx(file, fx, seconds)`; output is
trimmed/padded to the exact scene length (`apad`, `-t`) so timings never drift.
Pitch shifting is `asetrate` × factor + `atempo` 1/factor (changes pitch, keeps
duration).

| fx | chain (see `FX_FILTERS`) | use |
|---|---|---|
| `deep` | pitch ×0.88, bass +4 dB @140, small echo | gritty narrator |
| `growl` | pitch ×0.88, compressor 6:1, +4 dB, `tanh` soft clip (rasp), presence EQ @2.2 kHz, treble −5, bass +4, tight room, limiter | Batman |
| `villain` | pitch ×0.80, bass +8, triple echo, limiter | one threat line / evil laugh |
| `theatre` | no pitch, stage reverb | showmen, Jhin |
| `young` | pitch ×1.12, treble +2, short echo | kids, sidekicks |
| `mask` | pitch ×1.04, highpass, presence +4 dB @1.9 kHz, two short metallic echoes (9/17 ms) + stage room | Jhin — refined voice behind porcelain |

## 3. Clip scenes and laughter (Bark)

TTS cannot laugh — "ha ha ha" is read as words. A scene may instead use a
`clip` (`projects/<slug>/clips/*.wav`) with an optional caption.

`vb-audio laugh --out projects/<slug>/clips --count 4 [--voice v2/en_speaker_6] [--prompt ...]`
runs `suno/bark-small` for several seeds and scores each candidate by
**3–7 Hz amplitude modulation** (the syllable rate of laughter) in
`laugh.py::laugh_score`, writing `candidates.json` ranked. Pick one, copy it to
`laugh.wav`, and reference it from the manifest.

To make a laugh sound like the narrator, pitch-match it:
`uv run --project py python -m vb_audio.pitch a.wav b.wav` prints the median F0
(autocorrelation over voiced 40 ms frames). Choose the candidate whose F0 is
closest to the narrator's, or run it through the same `voiceFx` (FX apply to
clips too).

## 4. SFX and music

`assets/sfx/*.wav` and `assets/music/*.wav` are procedurally generated by
`assets/generate_assets.py` (no third-party rights). Names must also be in
`SFX` in `catalog.ts`. The resolver copies used assets into
`build/assets/` so Remotion can `staticFile()` them.

Loudness rules (2026-09-19, after the owner's "sound is a bit annoying" review and "cheer/whoosh
are radio static"):
- every SFX file is normalised to **−20 dBFS active RMS** (`loudnorm()` in the generator; peaks capped at
  0.95), with extra trims for piercing ones (`TRIM_DB`: glitch −5, error/whistle/thunder −4, ding −3, …).
  Before this, glitch sat at −7 dB and gunshot at −21 — a `volume: 0.8` meant nothing;
- the resolver multiplies every cue's `volume` by `SFX_GAIN = 0.8` (catalog) — effects under the voice;
- **no white noise**: whoosh/swoosh are pink noise through a gliding resonant band-pass (energy above
  4 kHz went from 54 % to 1 %), cheer is 40 formant-filtered voices + claps (no noise bed), thunder uses
  pink noise, glitch is low-passed at 2.4 kHz; the lo-fi loops lost the vinyl crackle and the noisy snare
  (HF energy 22 % → 0.2 %). One-pole `lowpass()` is not a filter that removes hiss — use `bandpass()`
  (scipy) for anything noise-based.

In the renderer, music is ducked under speech (`audio/Music.tsx`) and every SFX
drops to 38 % while a word is being spoken near it, so effects never mask
dialogue. Avoid noisy sustained effects (`thunder`, `glitch`) under lines
anyway — at Shorts playback levels they read as static.

## 5. Mastering and QA

`render.ts` muxes the Remotion output with all scene audio and runs
`loudnorm` to **−14 LUFS** (platform target), forcing `-ar 48000 -shortest`
because loudnorm otherwise resamples to 96 kHz and adds ~0.13 s.
`qa.ts` checks duration vs resolved frames, loudness (`volumedetect`), and that
luminance never drops out except inside declared `blackout`/`flash` windows.

## 6. Environment notes (Windows)

- `uv` and `ffmpeg` come from winget. Git Bash sessions started before the
  install do not see them; either open a new shell or prepend the winget
  `Packages/...` bin folders to `PATH`.
- Kokoro downloads `hexgrad/Kokoro-82M` on first use; Bark downloads
  `suno/bark-small`. Both run on CPU (torch CPU index in `py/pyproject.toml`).

## 7. Second engine: Chatterbox (trial — D13)

`"engine": "chatterbox"` on the manifest or a scene routes that scene to `py-chatterbox/`
(`vb_chatterbox`, its own uv env: chatterbox pins torch 2.6 CUDA). Everything downstream
reads the same `alignment.json`.

| field | where | meaning |
|---|---|---|
| `engine` | manifest / scene | `kokoro` (default) or `chatterbox` |
| `voiceRef` | manifest / scene | reference clip > 5 s: a file in `assets/voices/` (shared, with a card in its README) or the project's `clips/`. Required when the text has tags; optional otherwise (built-in voice) |
| `emotion` | manifest / scene | 0..1 acting intensity → `exaggeration` (0.5 if omitted). ≥ 0.7 also raises pitch and speeds up (we lower `cfg_weight` to 0.3 to compensate). Deep voices: ≤ 0.5 |
| `speech` tags | scene | `[laugh] [chuckle] [cough]` → the **Turbo** model performs them (needs `voiceRef`; ignores `emotion`). Stripped from captions/alignment; rejected when the engine is Kokoro |
| `speed` | manifest / scene | applied as ffmpeg `atempo` after synthesis, before alignment. Chatterbox paces itself — use ~0.9–1.05, not Kokoro's 0.78 |
| `voiceFx` | manifest / scene | unchanged; applied after alignment (length-preserving) |

Pipeline per scene: generate (Turbo if tagged, else original) → resample 24 kHz → `atempo` →
trim padding → **forced alignment** (`vb_chatterbox/align.py`: torchaudio wav2vec2 CTC on the
known text, CTC bias −75 ms/−20 ms measured against Kokoro) → cut everything before the first
word (Chatterbox opens with a click or up to 1 s of air) → `pauseAfter` → PCM16 wav → `voiceFx`.

Facts (GTX 1660 SUPER): model load 14 s; first generation ~45 s (CUDA warm-up); then 3–5 s per
line (rtf ~1.5 original, ~0.7 Turbo); `batman-alley` (9 lines) compiles in ~1.5 min cold, seconds
warm (cache key includes engine, emotion, and the reference file's size+mtime). Models: ~3 GB each,
downloaded once to `HF_HOME` (`F:\caches\hf`). Output carries Resemble's inaudible Perth watermark.

Non-verbal quality control: a tagged take is not guaranteed to contain the laugh (3 of 4 in the
experiments). If a `[laugh]` line sounds like plain speech, change `seed` by editing the text
trivially or re-run with `--force-audio` — and listen before shipping.

Research, measurements and the alternatives (Qwen3-TTS VoiceDesign, RVC, ElevenLabs…) live in
the sibling repo `F:/PoCs/audios` (`docs/06-decision-matrix.md`).
